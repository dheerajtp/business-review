# 06 — AI review generation with a configurable provider and key

Master plan: none (`SPEC.md` is updated in slice 05) · Builds on: [`../02-keyword-library/00-README.md`](../02-keyword-library/00-README.md), [`../04-company-keywords/00-README.md`](../04-company-keywords/00-README.md) (the branch's effective keywords)

## Goal
- Super Admin sets one global AI provider, model and API key (Gemini, Claude, OpenAI/GPT, or any OpenAI-compatible service) on an admin page. The key is write-only and stored encrypted.
- On the branch review page, after picking keywords, the customer can tap "Write my review with AI" to get a natural review draft built from the rating and the chosen keywords. The instant template draft stays as the default and as the fallback.
- The AI output is only a draft the customer edits; nothing is posted automatically.

| A1 | **Tables.** New migration `supabase/migrations/20261121000001_ai_review.sql` (never edit earlier ones). `ai_settings` singleton (`id boolean primary key default true check (id)`, `active_provider text null check (active_provider in ('gemini','anthropic','openai','custom'))`, `is_enabled boolean not null default false`, `daily_limit int not null default 2000 check (daily_limit between 1 and 100000)`, `updated_at timestamptz`), one row inserted. `ai_providers` (`provider text primary key` same check, `model text not null check (char_length(model) between 1 and 100)`, `base_url text null`, `secret_id uuid null`, `key_hint text null`, `updated_at`). `ai_generation_log` (`id uuid pk`, `branch_id uuid → branches`, `client_hash text`, `created_at timestamptz default now()`; indexes `(branch_id, client_hash, created_at)` and `(created_at)`). RLS enabled on all three; `revoke all` from anon and authenticated; **no direct grants to anyone** (access only through the RPCs below). |
| A2 | **Key storage and admin RPCs.** Keys live in Supabase Vault (`vault.create_secret`, `vault.update_secret`), secret name `ai_key_<provider>`; the table keeps only `secret_id` and `key_hint` (last 4 characters). All admin RPCs are security definer, `set search_path = public`, `revoke all from public`, execute to `authenticated`, and raise `42501 'forbidden'` unless `current_app_role() = 'super_admin'`:<br>`set_ai_provider(p_provider text, p_model text, p_base_url text, p_api_key text default null) returns void`: provider in the four values else `22023`; model 1–100 chars; `p_base_url` required for `custom`, optional for `openai`, must be null for `gemini`/`anthropic`; base URL rules in A6; `p_api_key` null/empty keeps the existing key, otherwise 8–400 chars with no whitespace, creates or updates the Vault secret and sets `key_hint = right(key, 4)`.<br>`clear_ai_provider_key(p_provider text) returns void`: deletes the secret, nulls `secret_id`/`key_hint`; if it was the active provider, sets `is_enabled = false`.<br>`set_ai_settings(p_active_provider text, p_is_enabled boolean, p_daily_limit int) returns void`: enabling requires the active provider to have a saved key (else `22023 'provider has no key'`); daily limit 1–100000.<br>`get_ai_settings() returns jsonb`: `{active_provider, is_enabled, daily_limit, providers:[{provider, model, base_url, has_key, key_hint, updated_at}]}`. It never returns a key or `secret_id`. |
| A3 | **Runtime RPCs for the Edge Functions (service role only).** security definer, `revoke all from public, anon, authenticated`, `grant execute to service_role`:<br>`get_ai_runtime() returns jsonb`: `{provider, model, base_url, api_key, daily_limit}` when `is_enabled` and the active provider has a key, else null.<br>`get_ai_provider_runtime(p_provider text) returns jsonb`: same shape for a named provider if it has a key, else null (used by the test function).<br>`get_review_context(p_slug text, p_keyword_ids uuid[]) returns jsonb`: null when the branch/company/subcategory/category is inactive or unknown; otherwise `{branch_id, company_name, branch_name, category_name, subcategory_name, labels:[text]}` where labels are the labels of the requested ids in request order, each of which must be active and in the branch's effective set (`effective_keyword_ids`, plan 04 M3), max 10 distinct, else `raise exception 'unknown keyword' using errcode = '22023'`.<br>`log_ai_generation(p_branch_id uuid, p_client_hash text) returns boolean`: false when the pair already has 6 rows in the last 10 minutes or the total in the last 24 hours is ≥ `daily_limit`; otherwise inserts a row and returns true. Rows older than 7 days are deleted opportunistically in this function. |
| A4 | **Form RPC.** `get_feedback_form(p_slug)` keeps every current field and adds `ai_enabled boolean` = `is_enabled` and the active provider has a key. Same signature, grants and not-found rules (drop and recreate). |
| A5 | **Edge Function `generate-review`** (`supabase/functions/generate-review/index.ts`, Deno, same style and CORS as `create-business-admin`; the customer calls it with the anon key via `supabase.functions.invoke`, default JWT verification stays on). POST `{slug: string, rating: 1–5 integer, keyword_ids: uuid[] (max 10)}`, body ≤ 4 KB else `413`; invalid input `400 {error}`. Flow: `get_review_context` (null → `404`, `22023` → `400`) → `get_ai_runtime` (null → `503 {error:'ai_unavailable'}`) → `log_ai_generation` with `client_hash` = first 32 hex chars of SHA-256 of the first `x-forwarded-for` address (empty string if absent) (false → `429 {error:'rate_limited'}`) → provider call with an 8 s timeout (A6) → sanitize → `200 {review}`. Any provider error, timeout or empty output → `502 {error:'ai_failed'}` with no provider detail. The key and the prompt are never logged or returned. |
| A6 | **Provider adapters.** `supabase/functions/_shared/providers.js` exports `generate({provider, model, base_url, api_key, system, user, maxTokens = 300, signal}) → string`:<br>`gemini`: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, header `x-goog-api-key`, body `{systemInstruction:{parts:[{text:system}]}, contents:[{role:'user',parts:[{text:user}]}], generationConfig:{maxOutputTokens:maxTokens, temperature:0.8}}`, text = joined `candidates[0].content.parts[].text`.<br>`anthropic`: `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`, body `{model, max_tokens, system, messages:[{role:'user',content:user}]}`, text = joined `content[].text` of type `text`.<br>`openai`: `POST {base_url or https://api.openai.com/v1}/chat/completions`, header `Authorization: Bearer`, body `{model, messages:[{role:'system',...},{role:'user',...}], max_completion_tokens}` (no temperature), text = `choices[0].message.content`.<br>`custom`: same as `openai` but `base_url` is required and the body uses `max_tokens` plus `temperature: 0.8`.<br>**Base URL guard** (checked in `set_ai_provider` in SQL and again in the adapter): `https://` only, length ≤ 300, host not `localhost`, not an IPv4/IPv6 literal, not ending in `.local` or `.internal`, no credentials in the URL; trailing slash stripped. |
| A7 | **Prompt (one function `buildPrompt` in `_shared/prompt.js`).** System: "You write short customer reviews for a business. Write 2 to 4 sentences in the first person, natural and plain text (no emojis, hashtags, quotes or markdown). Use only the business name, the rating and the keywords provided; do not invent details, names, prices, dates or staff. Include each keyword naturally, keeping its wording where it reads well. Match the tone to the rating: 4 to 5 warm and positive, 3 mixed, 1 to 2 honest and constructive, never insulting. At most 500 characters." User: `Business: {company_name} ({branch_name}); Type: {category_name} / {subcategory_name}; Rating: {rating} out of 5; Keywords: {labels joined by ", "}`. Sanitize: trim, strip wrapping quotes, collapse whitespace, cut to 600 characters; empty result = failure. Zero keywords is allowed (prompt says "Keywords: none"). |
| A8 | **Edge Function `test-ai`** (`supabase/functions/test-ai/index.ts`): Super Admin only, authenticated exactly like `create-business-admin` (401 not signed in, 403 not super_admin). Body `{provider: string}`; loads `get_ai_provider_runtime`, sends a fixed sample context ("Sample Cafe", rating 5, keywords "friendly staff, great coffee") through the same adapter with an 8 s timeout. Returns `200 {ok:true, sample}` or `200 {ok:false, reason}` where `reason` is one of `no_key`, `auth`, `model`, `network`, `timeout`, `unknown` (mapped from HTTP 401/403 → `auth`, 404/400 → `model`, fetch failure → `network`, abort → `timeout`). Never echoes the key or raw provider messages. |
| A9 | **Admin page `/admin/ai`** (Super Admin only, sidebar "AI review" under Set up, lazy route in the Super Admin group). Provider selector (Gemini, Claude (Anthropic), OpenAI (GPT), Custom (OpenAI-compatible)). Per provider: model text input (placeholder suggestions `gemini-2.5-flash`, `claude-haiku-5-5`, `gpt-4o-mini`; editable, no hard-coded allow-list), base URL (custom required, OpenAI optional, hidden for the others), API key as a password field that is write-only (shows "Saved, ending 1234" from `key_hint`; leaving it empty keeps the key), buttons Save (calls `set_ai_provider`), Test (calls `test-ai`, shows the sample or the mapped reason), Remove key (`clear_ai_provider_key`, confirm dialog). Global section: active provider select, "Enable AI reviews" toggle, daily limit number (`set_ai_settings`). Data via `get_ai_settings`. RPC errors mapped to plain messages. The key is held only in component state while typing and cleared after Save. |
| A10 | **Customer UI.** When the form RPC returns `ai_enabled` true and at least one keyword is selected, show the button "Write my review with AI" under the keyword chips (disabled while loading, `aria-busy`, 10 s client timeout). It calls `supabase.functions.invoke('generate-review', { body: { slug, rating, keyword_ids } })`. Success: put `review` into the existing comment textarea, set `edited` true (the template stops overwriting it), change the button to "Regenerate", and show "Suggested by AI. Edit it so it matches your visit." Failure or 502/503: keep the current text, show "Couldn't generate right now. You can edit the text below." `429`: "Please try again in a few minutes." The template draft (plan 02 K8) is unchanged and remains the default. Button hidden when `ai_enabled` is false. The Google button, copy button and low-rating card are unchanged. The submitted comment is whatever is in the textarea. |
| A11 | **Safety.** The key exists only in Vault and in the Edge Function's memory for the duration of a call; it is never sent to the browser, logged, or included in errors. Keyword ids and the rating are validated on the server; the customer cannot choose the model, provider, prompt or length. Rate limits per A3. The Edge Functions use the service-role client only for the RPCs above. |
| A12 | **Tests.** `supabase/tests/00_stubs.sql` gains a minimal `vault` schema stub (`vault.secrets`, `vault.create_secret(text, text, text) returns uuid`, `vault.update_secret(uuid, text, text, text)`, view `vault.decrypted_secrets`) so tests run on plain Postgres. `supabase/tests/rls.sql` adds: no role can select or write `ai_settings`, `ai_providers`, `ai_generation_log` directly; admin RPCs allowed for super admin and `42501` for business admin and anon; `get_ai_settings` output never contains the key or `secret_id`; null key keeps the existing key, a new key replaces it and updates `key_hint`; enabling without a key is rejected; `custom` rejects `http://`, `https://localhost`, an IP literal and a `.internal` host; runtime RPCs are not executable by anon/authenticated; `get_review_context` valid, unknown slug, inactive branch, keyword outside the effective set, more than 10 ids; `log_ai_generation` allows 6 then refuses the 7th for the same client, and refuses when the daily limit is reached; `get_feedback_form.ai_enabled` is false until enabled with a key. |
| A13 | **Out of scope (later).** Per-company keys, editable prompts or tone options, streaming, usage and cost dashboards, multiple languages, automatic generation on every change, using the AI for anything other than review drafts, key rotation reminders. |
| A14 | **Wording and policy.** Customer-facing text calls the result a suggestion to edit and never claims it is the customer's own words. Google's review policies require reviews to reflect real experience, so the draft is never submitted or posted by the app; the customer reads, edits and posts it. |
