## Known gaps (not fixed here)

- `web/src/styles.css` line 614: `.tax-grid` is still 3 columns on wide screens (`@media (min-width: 1000px)`); the Categories page now has two sections, so 2 columns is intended. Outside this slice's scope (slice 02 Result).
- `web/src/admin/CategoriesPage.jsx` line 55: `const [subId, setSubId] = useState(null);` is unused (only the declaration matches `subId`).
- Chips on `/f/{slug}` appear only after the first star tap (slice 03 Result), not on page load.
- The migration drops the old constraint and indexes by auto-generated names (`keywords_label_check`, `keywords_subcategory_label_lower_key`, `keywords_subcategory_id_is_active_idx`). If a live database has different names, the migration fails before any change is made to the seed; check the names before applying.
- `set_branch_keywords` takes an extra row lock on the branch (`select ... for update`) to serialise concurrent saves. This is intentional but not load-tested.
- Plan 01 known gaps still apply: `.notif-req` CSS is unused, `GetStarted.jsx` is not rendered, `categories_name_lower_key` can fail on a live database with names differing only by case, and the migration wipes companies, branches, feedback and Business Admin logins (owner must back up first).
