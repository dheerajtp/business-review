# 12 — AI models stored in a table and picked from a dropdown

Master plan: none (`SPEC.md` gets a short update in slice 02) · Builds on and amends: [`../08-ai-diagnostics-and-models/00-README.md`](../08-ai-diagnostics-and-models/00-README.md) (G2, G3: Load models now stores results; the model input becomes a dropdown) and [`../11-ai-resilience/00-README.md`](../11-ai-resilience/00-README.md) (F8: the fallback model uses the same dropdown)

## Goal
- On `/admin/ai`, the Model and Fallback model fields are dropdowns filled from a database table, not free text with hard-coded suggestions.
- The table is filled by **Load models** (which asks the provider for the models your key can use) and can be topped up by hand with **Add model**.
- No model names are hard-coded anywhere: the old suggestions (`gemini-2.5-flash`, `claude-haiku-5-5`, `gpt-4o-mini`) are removed.

## Decisions (already made; do not revisit)
| # | Decision |
| --- | --- |
| L1 | **Table.** New migration `supabase/migrations/20261126000001_ai_models.sql` (never edit earlier ones): `ai_models(provider text not null check (provider in ('gemini','anthropic','openai','custom')), model_id text not null check (char_length(model_id) between 1 and 100), label text null check (label is null or char_length(label) <= 100), is_available boolean not null default true, source text not null check (source in ('provider','manual')), created_at timestamptz not null default now(), updated_at timestamptz not null default now(), primary key (provider, model_id))`. RLS enabled, `revoke all` from anon and authenticated, no policies, no grants. **No seed rows** (model names change too often to hard-code; the table starts empty). |
| L2 | **Admin RPCs** (security definer, `set search_path = public`, `revoke all from public, anon`, `grant execute to authenticated`, `42501 'forbidden'` unless `current_app_role() = 'super_admin'`):<br>`list_ai_models(p_provider text default null) returns jsonb`: array of `{provider, model_id, label, is_available, source}` ordered by `provider, model_id`, filtered to the provider when given (invalid provider `22023`).<br>`add_ai_model(p_provider text, p_model_id text, p_label text default null) returns void`: provider valid; `p_model_id` trimmed, 1–100 chars matching `^[A-Za-z0-9._:/-]+$` else `22023 'invalid model id'`; inserts with `source = 'manual'`, or when the row exists sets `is_available = true` and keeps its source.<br>`remove_ai_model(p_provider text, p_model_id text) returns void`: deletes only rows with `source = 'manual'`; a `provider` row raises `22023 'synced models cannot be removed'`; a model that is the provider's saved `model` or `fallback_model` raises `22023 'model in use'`; unknown row = no-op. |
| L3 | **Sync RPC (service role only).** `sync_ai_models(p_provider text, p_models text[]) returns int`, security definer, `revoke all from public, anon, authenticated`, `grant execute to service_role`. Provider valid; null = empty; at most 500 ids else `22023 'too many models'`; each id trimmed and must match the L2 pattern (invalid ids are skipped, not an error); upserts every id with `source = 'provider'`, `is_available = true`, `updated_at = now()` (an existing manual row of the same id becomes `provider`); then sets `is_available = false` on existing `source = 'provider'` rows of that provider that are not in the list; manual rows are never touched. Returns the number of ids stored. |
| L4 | **Edge Function.** `supabase/functions/test-ai/index.ts`, action `list_models`: after `listModels(...)` succeeds, call `sync_ai_models(provider, models)` through the service-role client (awaited, 3 s race; failure is caught). Response `{ ok:true, models, stored: <true when sync returned without error> }`. Failure responses, authentication, the 8 s timeout and the other actions are unchanged. The list cap in `listModels` (200) stays. |
| L5 | **Admin UI** (`web/src/admin/AiSettingsPage.jsx`). Load the table once with `list_ai_models()` and keep it in page state, reloaded after Load models and after add/remove. In each provider card the **Model** and **Fallback model (optional)** inputs become `<select>` elements listing that provider's models with `is_available`, label = `model_id`; the saved value is always shown even when it is not in the list or unavailable, suffixed " (not in list)" or " (unavailable)". Model has a disabled first option "Select a model…" and is required; Fallback has the first option "None". Remove the `<datalist>`, the `placeholder` model suggestions and any hard-coded model names. Next to the dropdown: the existing **Load models** button (now stores the list and refreshes the dropdowns; hint "N models loaded" or the existing failure text), plus **Add model**: a small text input and button that calls `add_ai_model` (needed for Custom providers without a `/models` endpoint and as an escape hatch), and a **Remove** link shown for a selected manual model that calls `remove_ai_model`. When the provider has no models yet, show "Click Load models to fill this list, or add a model name." Error messages: `invalid model id` → "Use letters, numbers and . _ : / - only."; `synced models cannot be removed` → "Loaded models can't be removed; they refresh with Load models."; `model in use` → "That model is selected for this provider."; `forbidden` → "Only a Super Admin can change this." |
| L6 | **No coupling in the DB.** `set_ai_provider` and `set_ai_fallback_model` keep accepting any model string (the dropdown is a UI constraint). Existing saved models keep working and appear in the dropdown as the saved value. |
| L7 | **Tests.** `supabase/tests/rls.sql`: `ai_models` not readable or writable directly by any role; `list_ai_models` and `add_ai_model`/`remove_ai_model` allowed for super admin and `42501` for business admin and anon; `add_ai_model` rejects `bad id!` and 101 characters, makes a manual row, is idempotent; `remove_ai_model` deletes a manual row, refuses a provider row and a model in use (saved model or fallback); `sync_ai_models` is not executable by anon or authenticated, upserts provider rows, marks missing provider rows unavailable, never touches manual rows, converts a manual row that the provider lists into `provider`, skips invalid ids, rejects more than 500, returns the stored count. |
| L8 | **Node check (slice 02, scratchpad only).** With a mocked Supabase client, `list_models` calls `sync_ai_models` with the provider and the ids and still returns the models when the sync call throws (`stored:false`). |
| L9 | **Out of scope (later).** Seeding default model names, scheduled automatic syncing, descriptions, prices or capability flags per model, hiding models by capability, per-company model lists. |
